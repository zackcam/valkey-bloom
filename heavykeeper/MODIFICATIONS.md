# Local Modifications to heavykeeper

Changes applied to the vendored `heavykeeper` crate, in the order they were
committed on top of the upstream `main` import. Each row explains what the
change does and why we want it. Commit links point at
`detemmienation/valkey-bloom`.

Baseline: [Integrate heavykeeper-rs as a local path dependency] vendors
upstream heavykeeper-rs at tag `v0.7.1` (commit `a5191aa`, tip merge
`d410785`, https://github.com/pmcgleenon/heavykeeper-rs) so we can modify
it in-tree. That baseline already ships upstream's native byte
serialization for `CuckooTopK`/`BucketedTopK`, the shared serialization
module (magic bytes, variant tag, on-load hasher probe), RDB-format
hardening, and the priority-queue redundant-lookup perf fix. Cells default
to `u64`.

| 5 | Single-copy priority queue + drop free-slot list | Store each tracked item once (`hashbrown::HashTable<u32>` maps to a slot index instead of duplicating the key), halving per-item memory in the PQ. | 6 | Narrow `sequence` to `u32` | The PQ tie-break `sequence` fits in `u32`; halves that field. Uses `wrapping_add` to avoid overflow panics. | Only matters past ~4.3B inserts, at which point tie ordering can wrap (acceptable, matches upstream). | [41fa47b](https://github.com/detemmienation/valkey-bloom/commit/41fa47b9f638da3e76220a17b4d602514f963731) |
| 7 | Remove decay-threshold lookup table | Drop the 1024-entry `u64` precomputed table; compute `decay^count` directly with `powf`. Saves the table's memory (~8 KB/sketch). | Kept because it most benefits small `k`. Trade-off: a `powf` per lobby-decay check instead of an O(1) table lookup. | [97a0735](https://github.com/detemmienation/valkey-bloom/commit/97a07356cd99eb3b34d937270fa4afd2ab389968) |
| 8 | Linear-scan PQ lookup (default) | Add a runtime lookup strategy: `CuckooTopK` defaults to a linear scan over `item_store` instead of the hash table, leaving the table unallocated. Better cache locality for small `k` and no hashing on the lookup path. | Default; opt into the hash table per key (see #9). | [d508c78](https://github.com/detemmienation/valkey-bloom/commit/d508c780a4687be86fccf96c0bc46f4ddbdc8ead) |
| 9 | Per-key `HASHMAP` option | Make the lookup strategy selectable per key: `TOPK.RESERVE ... HASHMAP` opts into the hash table (default stays linear). The flag is persisted in the sketch's serialized bytes so it survives RDB/AOF restore, and is replicated so replicas build the same structure. | Follow-up to #8: turns the compile-time-only default into a per-key choice. Threaded through serialization → `TopKObject` → the command; strategy round-trips and replicates. | [90dd60b](https://github.com/detemmienation/valkey-bloom/commit/90dd60b10a5f3c560980b67ea3786d592773f968), [abb0053](https://github.com/detemmienation/valkey-bloom/commit/abb0053e1ba3722cb56a221ba48072c4ffbfa109), [c3d74a9](https://github.com/detemmienation/valkey-bloom/commit/c3d74a9ec3c9f0072d8cb1755f4fbbcf8c79ccfe) |
| 10 | Self-describing cell widths in serialization | Record `size_of::<F>()`/`size_of::<C>()` in the cuckoo payload and validate them on load (`CellWidthMismatch`). Folded into the initial format version (nothing released yet). A stream written by one width instantiation now fails loudly instead of misparsing when read by another (e.g. after the u64 to u32 switch in #4). | Hardening follow-up to #3/#4. | local |
| 11 | Renumber PQ sequence on wrap | Replace `wrapping_add` with a `next_sequence()` helper: at `u32::MAX` the live slots are renumbered in relative order (O(k log k), once per 2^32 assignments), so count-tie ordering never degrades. | Hardening follow-up to #6; regression test added. | local |
| 12 | Hoist decay threshold out of the per-unit loop | `decay_threshold()` (a `powf`) is recomputed only when the cell count changes instead of once per unit of increment, so a large `TOPK.INCRBY` no longer pays one `powf` per unit on the main thread. | Hardening follow-up to #7. | local |
| 13 | PQ robustness: eviction assert + `allocation_size()` | The eviction path now `debug_assert`s if the displaced item is missing from the lookup table (silent desync before), and `mem_bytes` uses hashbrown's own `allocation_size()` instead of hand-rolled bucket math that could drift across hashbrown upgrades. | Hardening follow-up to #5. | local |
| 14 | Replace `ahash` with seeded SipHash-1-3 (`SipState`) | `ahash` output varies by CPU architecture, feature set, and crate version, so serialized sketches could only be restored on the platform that wrote them (the hasher probe failed the load otherwise). SipHash-1-3 is a frozen spec: identical output everywhere, so RDBs are portable across x86_64/aarch64 and crate upgrades, matching the bloom side's portability (the `bloomfilter` crate already uses SipHash keys). Keys derived from the sketch seed via splitmix64; keyed hashing retains DoS resistance. `ahash` dependency removed. | Folded into the initial format version (nothing released yet). Cross-platform pin test added in `sip.rs`. | local |
| 15 | Layout-derived up-front size estimate | Add `CuckooTopK::estimated_mem_bytes()` and `TopKQueue::entry_mem_bytes()` so the module's `TOPK.RESERVE` size check derives per-cell and per-entry costs from the real types instead of hardcoded constants (8 bytes/cell, 128 bytes/entry) that silently drift if the cell width or slot layout changes. Test pins the estimate as an upper bound of actual structural `mem_bytes`. | Companion to the module-side `estimated_size()` rewrite. | local |
